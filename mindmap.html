AI Job Copilot, end to end

The core pipeline sits in the middle. Entry points, graphs, agents and portals run along the right. Objectives, guardrails, models, config and storage support it from the left.

How the parts connect

Search to PDF

discover asks a Portal to search, skips blacklisted or known jobs, fetches details, then runs POSTING_GRAPH: analyze, score, tailor, Honesty Guard, render PDF, save to the tracker.

Honesty first

The LLM only proposes. guard() checks every proposal against the SkillBank built from profile.yaml and reverts anything unverified.

Review, then apply

Jobs land as PENDING_REVIEW. Approved jobs go through APPLY_GRAPH, which enforces daily and per-portal caps before the portal's apply runs.

One engine, many doors

CLI, MCP tools, the Gemini chat agent and the FastAPI backend all call the same async pipeline functions. The React UI talks to FastAPI.

Works without a model

With no provider configured, agents get llm=None and use heuristics. That is why --source sample and the tests run offline.

Daily loop

DAILY_GRAPH runs discover, applies only in auto mode, then builds the Excel report and emails it over SMTP.
